Техническое задание (ТЗ) на разработку корпоративного сайта Управляющей Компании (УК)
1. Общие сведения о проекте
	•	Цель проекта: Создание имиджевого и информационного сайта для Управляющей Компании.
	•	Референс по дизайну: sminex.com
	•	Дизайн-код и визуальные требования: Использование тонких шрифтов, сдержанная цветовая палитра, большое количество «воздуха» в макетах, тонкие изящные линии.
	•	Особенности реализации: На первом этапе сайт реализуется как статический (без CMS / административной панели).
2. Структура страниц и функциональные блоки (Фронтенд)
Главная страница
Секция 1: Главный экран (Hero)
	•	Визуал: Полноэкранный фоновый видеоролик (материалы предоставляются Заказчиком).
	•	Функционал: Автовоспроизведение видео (без звука по умолчанию), наложение логотипа и базовой навигации.
Секция 2: «Наши ЖК» (Анонс)
	•	Визуал: Блок текста с описанием и кнопка/ссылка «Наши ЖК».
	•	Функционал: При клике осуществляется переход на отдельную внутреннюю страницу (см. раздел «Страница Наши ЖК / Карта»).
Секция 3: Имиджевый блок
	•	Визуал: Крупный типографический заголовок, текстовый блок, слайдер с фотографиями.
	•	Функционал: Плавное перелистывание слайдера (навигация по клику и свайпу для мобильных устройств).
Секция 4: Преимущества компании
	•	Визуал: Карточки с ключевыми показателями в цифрах (количество обслуживаемых домов, количество жильцов, охват регионов и т.д.).
	•	Функционал (Интерактив): При наведении (hover) на карточку с цифрой происходит смена контента — появляется дополнительный поясняющий текст и/или фоновое изображение.
Секция 5: Аварийно-диспетчерская служба
	•	Визуал: Крупный заголовок, текст, слайдер с рабочими фотографиями службы. Акцент на круглосуточную работу (24/7), телеметрию систем пожарной безопасности и мониторинг оборудования в режиме онлайн.
Секция 6: Новости
	•	Визуал: Разделенный экран (референс: блок «забота о клиенте» на sminex). Справа располагается список новостей (карточки или вертикальный слайдер). Слева — область просмотра контента.
	•	Функционал:
	◦	При наведении на карточку новости справа, в левой части экрана динамически подгружается фотография и текст соответствующей новости.
	◦	Текст новости обрезается троеточием (в случае превышения лимита строк).
	◦	Имеется кнопка «Прочитать новость целиком», ведущая на внутреннюю страницу отдельной новости.
Секция 7: Мы в СМИ
	•	Визуал: Журнальная верстка (блоки располагаются асимметрично: левее/правее).
	•	Контент: Цитаты из прессы (оформленные кавычками), данные об источнике упоминания, иллюстрация (фото статьи/журнала).
	•	Функционал: Кнопка-ссылка, ведущая на внешний ресурс с оригиналом статьи.
Секция 8: Должники
	•	Контент: Информационный список должников (без цели пристыдить, сухой информационный формат). Включает: номер квартиры, количество месяцев задолженности, адрес ЖК.
	•	Функционал: Статичный список или таблица (данные предоставляются Заказчиком).
Внутренние страницы
Страница «Наши ЖК (Карта)»
	•	Визуал: Интерактивный блок с картой и списком регионов (Краснодар, Адыгея, Калининград и др.).
	•	Функционал:
	◦	При клике на метку конкретного ЖК меняется медиа-контент (фото/видео) и отображается текстовая информация о деятельности УК в данном доме (структура, количество квартир, квадратура).
	◦	Примечание: Техническое решение для реализации карты (Яндекс, Google, кастомная SVG-графика) будет согласовано и уточнено на следующих этапах разработки.
	•	План масштабирования (в будущем): Интеграция интерактивных 3D-моделей домов (при наведении на часть модели всплывает информация).
Страница «Отдельная новость»
	•	Визуал: Стандартный шаблон статьи (крупная фотография, заголовок, форматированный текст новости).
Страница «Документы»
	•	Визуал: Структурированный список файлов для скачивания. Доступ на страницу осуществляется через главное меню сайта.
	•	Логика: Жесткое разделение документов на категории:
	◦	Общие документы компании.
	◦	Документы, относящиеся к конкретным ЖК (по городам и адресам).
	•	Функционал: Возможность скачать файл или открыть его для просмотра в браузере.
3. Администрирование и контент
	•	CMS (Система управления контентом): Не предусмотрена.
	•	Обновление данных: Добавление новостей, обновление списков должников и управление документами осуществляется Заказчиком самостоятельно напрямую в коде сайта (HTML/JSON файлы).
	•	Исполнитель (разработчик) оказывает Заказчику технические консультации по процессу обновления контента.
4. Хостинг и хранение файлов
	•	Хостинг: Предварительно выбран обычный статический хостинг. Точная конфигурация и провайдер будут уточнены позже.
	•	Хранение файлов: Документы из раздела «Документы» загружаются и хранятся в виде обычных файлов в директории прямо на хостинге сайта.

Документ составлен для согласования с Заказчиком. Любые функции, не описанные в данном ТЗ, оцениваются как дополнительная разработка.
